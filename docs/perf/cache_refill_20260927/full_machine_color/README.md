# Full-machine Color 8-bit cache refill comparison

This is one matched baseline/candidate simulator pair using the opt-in retained-RAM-line model. Each variant ran the same saved Color 8-bit control stream, with a final `quit` appended after its original terminal wait, an independent writable copy of the same golden Speedometer 4.02 disk, identical release CPU defines, and the same model parameters. Both completed with exit status 0. The runs are simulator evidence only; they do not establish hardware behavior.

The final screenshots show 9.878 seconds and rating 1.072 for baseline, versus 9.807 seconds and rating 1.080 for candidate, both at one iteration. Candidate elapsed time is 0.71877% lower; the speed ratio calculated from those times is 1.00724 (about 0.72% faster). This is one paired run, so treat the small difference as preliminary rather than a repeatable performance claim.

The CPU profile covered the same fixed 524,160,000-cycle bracket in both variants. It reports baseline 93,973,496 opcode dispatches / 5.578 clocks per dispatch and candidate 95,514,940 / 5.488 clocks per dispatch. The matching profile start cycle was 3,592,624,051. Fixed-window profile counts and completed-fill counts reflect the executed mix and are not direct same-work speedup measures. Report reconciliation passed in both runs.

The refill profiler's region averages (baseline → candidate) were RAM data 11.010 → 8.993 clocks per completed fill, RAM instruction 11.165 → 9.175, ROM data 10.503 → 10.495, and ROM instruction 11.146 → 11.147. Partial-fill starts/ends/aborts were 1/0/0 in each run. Completed fills were 8,422,485 → 8,758,838; this count difference is workload-mix variation within the fixed window, not itself evidence of speedup.

Both variants used `+ram_line_model +ram_first_latency=4 +ram_line_publish_delay=2`, Verilator 5.050, `--unroll-count 256`, and release defines `AP040_EXPERIMENTAL_XSTORE AP040_EXPERIMENTAL_LEA AP040_EXPERIMENTAL_PIPELINE AP040_EXPERIMENTAL_PIPELINE_LOADS AP040_EXPERIMENTAL_PIPELINE_STORES AP040_EXPERIMENTAL_PIPELINE_PEA AP040_EXPERIMENTAL_PIPELINE_P6 AP040_PIPELINE_MEMORY_ENTRY AP040_PIPELINE_COMPARE AP040_PIPELINE_EARLY_DRAIN SCSI_CACHE_OFF`. Model `sim.v` SHA256: `372f1a1988c55a900d45132bfde6e251e439143c299464081886c39dbf878c36`. Baseline and candidate build manifests are included as `baseline_build_manifest.txt` and `candidate_build_manifest.txt`; the run status files record each binary hash and launch identity. Each variant subdirectory also retains the exact command script, control input, CPU profile TSV, run metadata and selected screenshots.

The final screenshots differ, as expected for timing/output content. Setup screenshots at frames 1667 and 4277 are byte-identical between the pair. Per-file SHA256 hashes are listed in `SHA256SUMS.txt`. Compact exact-path log milestones are included with each variant; the original large logs and mutable disk images remain in the scratch run trees and were not copied here.
