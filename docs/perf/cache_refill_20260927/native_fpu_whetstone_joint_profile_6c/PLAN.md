## Cycle cross-tab

Invoke a `next_sample` task FIRST in the existing main `always @(posedge clk_sys)` block, before its blocking `cycles++` or `in_loop` marker updates. Use pre-NBA signals and the old `in_loop` value, as the original occupancy monitor does. No separate competing always block, additional edge/eval, CE manipulation or pause. The start-marker edge is excluded, stop-marker edge included; this matches the existing loop counter convention. Assert samples equal original loop clocks. A return to reset inside the window is a failure rather than silently clearing counts.

One mutually exclusive PC bucket per sampled edge, from `dut.cpu.core.pc_i`:

- ROM:40800000<=PC<40900000.
- Native body:60029a<=PC<6006a2.
- Remaining resource:600000<=PC<600ec8 excluding body.
- Other:everything else (including entry stub, vectors/trap context outside those ranges).

These exact ranges are the pinned resource/body ranges used by existing `native_body/native_resource/native_rom` counters, not new guessed labels. PC is sequencer occupancy context; it does not identify a retired instruction or the owner of speculative fetches.

One mutually exclusive CPU bucket: MRD (state9), DEC-blocked (state153 && fpu_bg && !fpu_done), GO (state160), Other. Different state values cannot overlap. FPU bucket is exact `dut.cpu.core.g_fpu.fpu.fst`0..31; sample `r_op`0..127 only for non-IDLE busy-op cross-tabs. Direct background/done fields are `dut.cpu.core.fpu_bg/fpu_done`. Keep raw state/op occupancy semantics, not operation/transaction counts. Reject invalid state/op indexes BEFORE array writes, with no masking.

Bounded counters: `joint[4][4][32]` (512 uint64 counters), `busy_op[4][4][128]` (2,048), plus4-PC/4-CPU/32-FST margins. Report nonzero cells. Require sum(joint)=sample_edges=loop_clocks; every PC/CPU/FST projection equals its direct margin and original corresponding predicates. Require sum(busy_op)=sum(fst!=IDLE joint). Background activity may overlap any CPU bucket; emit `bg_joint[4][4]` separately and never add it to joint totals. This directly distinguishes ROM+MRD service from ROM+GO or DEC-blocked arithmetic wait.

## Memory episodes and cacheability

Use two separate, labeled observation planes; their episode totals are NOT additive. Existing wrapper muxing is essential: `rtl/wombat_cpu.sv:134-140` presents consistent mem_req/write/instr/size/addr/fc. Never pair wrapper request/ack with stale `core.mem_*_q` fields. Existing native TB CORE_LAT uses these wrapper signals (`tb_platform_whet.sv:278-284`).

1. **Logical wrapper episode:** start at the first edge with `dut.cpu.mem_req` and no active episode, complete on mem_ack/mem_flt/berr (ack can coincide with first request, latency1). Snapshot logical address, mem_instr/write/size/fc and observed sequencer PC/context. A fetch's requested logical address is separately available as its fetch-address context; a data episode's sequencer PC is explicitly diagnostic, not proven issuing-instruction PC. One outstanding presented episode fits the wrapper's locked `sel_instr` arbitration (`wombat_cpu.sv:101-160`). Do not overwrite metadata on held req; require request fields stable while active. Dropped req before completion is a cancellation/failure diagnostic, not successful retirement. Treat faults separately and require zero for this qualified fixture.

Snapshot actual cache input policy when this translated episode begins. Report two policy bits `{c_nocache,!ena}` and bypass separately: inhibited/disabled/misaligned/write bypass are not all equivalent to a cache miss. Snapshot immutability/one outstanding/completion rules as above, allowing immediate ack. Require translated completions never exceed logical completions; compare one-to-one completion counts if actual fixture trace confirms no terminal faults or window-boundary partials.
